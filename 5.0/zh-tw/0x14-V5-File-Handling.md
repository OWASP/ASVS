# V5 檔案處理

## 控制目標

應用在接收、儲存和提供檔案時，會面臨拒絕服務、未授權存取和儲存空間耗盡等風險。本章說明如何應對這些風險。

## V5.1 檔案處理說明文件

本節要求以文件記錄應用可以接收哪些檔案，以及這些檔案應具備哪些特徵。這些資訊是開發和驗證檔案安全檢查的前提。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.1.1** | 驗證說明文件針對每項上傳功能，規定了允許的檔案類型、預期的檔案副檔名和大小上限（包括解壓縮或解封裝後的大小）。說明文件還必須說明如何確保最終使用者能夠安全地下載和處理檔案，例如應用檢測到惡意檔案時應如何處理。 | 2 |

## V5.2 檔案上傳和內容

上傳功能是應用接收不可信檔案的主要入口。本節要求應用限制檔案的大小、數量和內容，避免上傳檔案危害應用。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.2.1** | 驗證應用只接受大小在其處理能力範圍內的檔案，且處理這些檔案不會造成效能下降或拒絕服務攻擊。 | 1 |
| **5.2.2** | 驗證應用接收檔案時，會檢查副檔名是否在允許範圍內，並確認檔案內容與副檔名表示的類型一致。此要求既適用於單獨上傳的檔案，也適用於 ZIP 等封存檔中的每個檔案。檢查方法包括但不限於檢查檔案開頭的識別位元組（magic bytes）、重新編碼圖片，以及使用專用函式庫驗證檔案內容。L1 可以只檢查用於作出特定業務或安全決策的檔案；L2 及以上必須檢查所有接收的檔案。 | 1 |
| **5.2.3** | 驗證應用在解壓縮或解封裝 ZIP、GZ、DOCX、ODT 等檔案之前，會檢查解壓縮後的總大小和檔案數量是否超過規定上限。 | 2 |
| **5.2.4** | 驗證應用限制每個使用者可儲存檔案的總大小和檔案數量，防止單個使用者通過上傳過多或過大的檔案耗盡儲存空間。 | 3 |
| **5.2.5** | 驗證應用拒絕包含符號連結的壓縮檔案。業務確實需要支援符號連結時，必須通過允許清單嚴格限制符號連結可以指向的檔案。 | 3 |
| **5.2.6** | 驗證應用拒絕像素尺寸超過最大允許值的上傳圖片，以防止像素洪泛攻擊。 | 3 |

## V5.3 檔案儲存

本節要求應用防止上傳的檔案被當作程式碼執行，識別其中的危險內容，並避免由不可信資料決定檔案的儲存位置。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.3.1** | 驗證由不可信輸入上傳或生成的檔案，即使存放在可公開存取的目錄中，也不會在通過 HTTP 直接存取時被伺服器端當作程式碼執行。 | 1 |
| **5.3.2** | 驗證應用執行檔案操作時，使用內部生成的資料或可信資料來構造檔案路徑，而不是直接使用使用者提交的檔名。確實需要使用使用者提供的檔名或檔案中繼資料時，必須進行嚴格驗證和淨化，以防範路徑遍歷、本機或遠端檔案包含（LFI、RFI）以及伺服器端請求偽造（SSRF）。 | 1 |
| **5.3.3** | 驗證伺服器端在解壓縮檔案等處理過程中忽略使用者提供的路徑資訊，以防範 Zip Slip 等弱點。 | 3 |

## V5.4 檔案下載

本節說明提供檔案下載時如何防範路徑遍歷和注入攻擊，並避免向使用者提供含有惡意內容的檔案。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.4.1** | 驗證應用會驗證或忽略使用者提交的檔名，包括通過 JSON、JSONP 或 URL 參數提交的檔名；下載回應中的實際檔名由應用在 Content-Disposition 標頭中明確指定。 | 2 |
| **5.4.2** | 驗證對外提供的檔名（例如 HTTP 回應標頭欄位或電子郵件附件中的檔名）經過編碼或淨化（例如遵循 RFC 6266），以維持文件結構並防止注入攻擊。 | 2 |
| **5.4.3** | 驗證來自不可信來源的檔案經過防毒軟體掃描，避免向使用者提供已知的惡意內容。 | 2 |
