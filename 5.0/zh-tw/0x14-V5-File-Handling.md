# V5 文件處理

## 控制目標

應用在接收、儲存和提供文件時，會面臨拒絕服務、未授權存取和儲存空間耗盡等風險。本章說明如何應對這些風險。

## V5.1 文件處理文件

本節要求記錄應用可以接收哪些文件，以及這些文件應具備哪些特徵。這些資訊是開發和驗證文件安全檢查的前提。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.1.1** | 驗證文件針對每項上傳功能，規定了允許的文件類型、預期的文件擴展名和大小上限（包括解壓或解包後的大小）。文件還必須說明如何確保最終使用者能夠安全地下載和處理文件，例如應用檢測到惡意文件時應如何處理。 | 2 |

## V5.2 文件上傳和內容

上傳功能是應用接收不可信文件的主要入口。本節要求應用限制文件的大小、數量和內容，避免上傳文件危害應用。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.2.1** | 驗證應用只接受大小在其處理能力範圍內的文件，且處理這些文件不會造成效能下降或拒絕服務攻擊。 | 1 |
| **5.2.2** | 驗證應用接收文件時，會檢查擴展名是否在允許範圍內，並確認文件內容與擴展名表示的類型一致。此要求既適用於單獨上傳的文件，也適用於 ZIP 等歸檔文件中的每個文件。檢查方法包括但不限於檢核文件開頭的「魔數」、重新編碼圖片，以及使用專用庫驗證文件內容。L1 可以只檢查用於作出特定業務或安全決策的文件；L2 及以上必須檢查所有接收的文件。 | 1 |
| **5.2.3** | 驗證應用在解壓或解包 ZIP、GZ、DOCX、ODT 等文件之前，會檢查解壓後的總大小和文件數量是否超過規定上限。 | 2 |
| **5.2.4** | 驗證應用限制每個使用者可儲存文件的總大小和文件數量，防止單個使用者通過上傳過多或過大的文件耗盡儲存空間。 | 3 |
| **5.2.5** | 驗證應用拒絕包含符號鏈接的壓縮文件。業務確實需要支援符號鏈接時，必須通過允許列表嚴格限制符號鏈接可以指向的文件。 | 3 |
| **5.2.6** | 驗證應用拒絕像素尺寸超過最大允許值的上傳圖片，以防止像素洪泛攻擊。 | 3 |

## V5.3 文件儲存

本節要求應用防止上傳的文件被當作程式碼執行，識別其中的危險內容，並避免由不可信資料決定文件的儲存位置。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.3.1** | 驗證由不可信輸入上傳或生成的文件，即使存放在可公開存取的目錄中，也不會在通過 HTTP 直接存取時被伺服器端當作程序程式碼執行。 | 1 |
| **5.3.2** | 驗證應用執行文件操作時，使用內部生成的資料或可信資料來構造文件路徑，而不是直接使用使用者提交的文件名。確實需要使用使用者提供的文件名或文件元資料時，必須進行嚴格驗證和淨化，以防範路徑遍歷、本地或遠程文件包含（LFI、RFI）以及伺服器端請求偽造（SSRF）。 | 1 |
| **5.3.3** | 驗證伺服器端在解壓文件等處理過程中忽略使用者提供的路徑資訊，以防範 Zip Slip 等弱點。 | 3 |

## V5.4 文件下載

本節說明提供文件下載時如何防範路徑遍歷和注入攻擊，並避免向使用者提供含有惡意內容的文件。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **5.4.1** | 驗證應用會驗證或忽略使用者提交的文件名，包括通過 JSON、JSONP 或 URL 參數提交的文件名；下載回應中的實際文件名由應用在 Content-Disposition 頭中明確指定。 | 2 |
| **5.4.2** | 驗證對外提供的文件名（例如 HTTP 回應頭欄位或電子郵件附件中的文件名）經過編碼或淨化（例如遵循 RFC 6266），以保持文件結構並防止注入攻擊。 | 2 |
| **5.4.3** | 驗證來自不可信來源的文件經過防病毒軟體掃描，避免向使用者提供已知的惡意內容。 | 2 |
