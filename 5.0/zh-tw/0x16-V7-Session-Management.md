# V7 工作階段管理

## 控制目標

即使底層使用 HTTP 這類無狀態通訊協定，工作階段管理機制也能讓應用在一段時間內識別並關聯同一使用者或裝置的多次互動。現代應用可能同時使用多種工作階段權杖，每種權杖的用途和特性各不相同。安全的工作階段管理系統必須防止攻擊者竊取、使用或以其他方式濫用他人的工作階段，並滿足以下總體要求：

* 工作階段對每個個體都是唯一的，不能被猜測或共享。
* 當不再需要工作階段時，工作階段會失效；在不活動期間，工作階段會逾時。

本章許多要求都與選定的 [NIST SP 800-63 Digital Identity Guidelines](https://pages.nist.gov/800-63-4/) 控制相關，重點關注常見威脅和常被利用的身分驗證弱點。

請注意，某些工作階段管理機制的具體實作細節要求可在其他章節中找到：

* HTTP Cookie 是保護工作階段權杖的常見機制。Cookie 的具體安全要求位於「Web 前端安全」章節。
* 自包含權杖經常用於維護工作階段。具體安全要求位於「自包含權杖」章節。

## V7.1 工作階段管理文件

沒有一種工作階段管理方案適合所有應用，也無法為所有場景規定統一的邊界和限制。因此，在實作和測試工作階段管理之前，必須先分析相關風險並記錄安全決策，確保最終方案符合應用的實際需求。

無論選擇有狀態還是「無狀態」工作階段機制，分析都必須完整並形成文件，以證明所選方案能夠滿足所有相關安全要求。還應考慮與任何正在使用的單一登入（SSO）機制之間的互動。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.1.1** | 驗證使用者工作階段的閒置逾時時間和工作階段絕對最長生命週期已記錄在文件中，並且這些限制與其他控制配合使用時是適當的。如果相關設定偏離 NIST SP 800-63B 的重新驗證要求，文件必須說明理由。 | 2 |
| **7.1.2** | 驗證文件規定了每個帳號允許同時存在的工作階段數量，以及達到上限時應用應如何處理。 | 2 |
| **7.1.3** | 驗證文件列出了聯合身分體系（例如 SSO 系統）中所有負責建立和管理使用者工作階段的系統，並說明各系統如何協調工作階段的生命週期、終止操作和重新驗證條件。 | 2 |

## V7.2 基礎工作階段管理安全

本節規定安全生成和驗證工作階段權杖的基本要求。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.2.1** | 驗證應用使用可信後端服務執行所有工作階段權杖驗證。 | 1 |
| **7.2.2** | 驗證應用使用動態生成的自包含權杖或引用權杖來管理工作階段，而不是使用靜態的 API 秘密和金鑰。 | 1 |
| **7.2.3** | 驗證應用使用引用權杖表示使用者工作階段時，每個權杖都具有唯一性，由密碼學安全偽亂數產生器（CSPRNG）生成，並且至少包含 128 位元熵。 | 1 |
| **7.2.4** | 驗證應用在使用者身分驗證（包括重新進行身分驗證）時生成新的工作階段權杖，並使當前工作階段權杖失效。 | 1 |

## V7.3 工作階段逾時

工作階段逾時機制用於盡量縮小工作階段劫持和其他工作階段濫用的機會窗口。逾時設定必須滿足已記錄的安全決策。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.3.1** | 驗證應用設定了工作階段閒置逾時，並按照風險分析和已記錄的安全決策，在逾時後強制使用者重新進行身分驗證。 | 2 |
| **7.3.2** | 驗證應用設定了工作階段絕對最長生命週期，並按照風險分析和已記錄的安全決策，在達到上限後強制使用者重新進行身分驗證。 | 2 |

## V7.4 工作階段終止

工作階段可以由應用自身終止；如果應用把工作階段管理交給了 SSO 提供方，也可以由 SSO 提供方終止。評估本節要求時，應判斷是否需要把 SSO 提供方納入驗證範圍，因為部分工作階段控制可能由它負責。

工作階段終止後應要求使用者重新進行身分驗證，且終止操作應在應用、聯合登入系統（如有）和所有依賴方生效。

對於有狀態工作階段機制，終止通常涉及在後端使工作階段失效。對於自包含權杖，需要額外措施來撤銷或阻止這些權杖，否則它們可能在過期前仍然有效。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.4.1** | 驗證工作階段被登出或過期等事件終止後，應用不再接受該工作階段。對於引用權杖或有狀態工作階段，這意味著在應用後端使相應工作階段資料失效。使用自包含權杖的應用需要採用相應方案，例如維護已終止權杖清單、拒絕某個使用者在指定時間之前簽發的權杖，或輪替該使用者的簽章金鑰。 | 1 |
| **7.4.2** | 驗證使用者帳號被停用或刪除時（例如員工離職），應用會終止該帳號的所有作用中的工作階段。 | 1 |
| **7.4.3** | 驗證使用者成功更改或移除任何身分驗證因素後，應用允許其終止所有其他作用中的工作階段。身分驗證因素的變更包括通過重設或復原流程修改密碼，以及更新已有的 MFA 設定。 | 2 |
| **7.4.4** | 驗證所有需要身分驗證的頁面都在醒目、易用的位置提供登出功能。 | 2 |
| **7.4.5** | 驗證應用管理員能夠終止單個使用者或所有使用者的作用中的工作階段。 | 2 |

## V7.5 防範工作階段濫用

本節提供相關要求，用於降低作用中的工作階段遭到劫持或濫用的風險。這類攻擊會利用使用者已登入的工作階段及其權限，例如通過執行惡意內容，強制已身分驗證使用者的瀏覽器借助其工作階段執行某項操作。

請注意，在考慮本節要求時，應同時參考「身分驗證」章節中針對不同等級的指導。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.5.1** | 驗證應用在允許使用者修改可能影響身分驗證的敏感帳號資訊之前，要求使用者重新完成完整的身分驗證。此類資訊包括電子郵件位址、電話號碼、MFA 組態，以及帳號復原所需的其他資訊。 | 2 |
| **7.5.2** | 驗證使用者可以查看自己的任一或全部作用中的工作階段，並能在使用至少一個身分驗證因素重新進行身分驗證後終止這些工作階段。 | 2 |
| **7.5.3** | 驗證應用在執行高度敏感的交易或其他業務操作之前，要求使用者使用至少一個身分驗證因素再次進行身分驗證，或者完成二次驗證。 | 3 |

## V7.6 聯合式重新驗證

本節與編寫依賴方（RP）或身分提供方（IdP）程式碼的人員相關。這些要求源自 [NIST SP 800-63C](https://pages.nist.gov/800-63-4/sp800-63c.html) 中關於聯合與斷言的內容。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **7.6.1** | 驗證依賴方（RP）和身分提供方（IdP）的工作階段生命週期及終止方式符合文件規定，並在需要時強制重新進行身分驗證。例如，當距離上一次 IdP 身分驗證達到規定的最長間隔時，應要求使用者重新進行身分驗證。 | 2 |
| **7.6.2** | 驗證建立工作階段必須得到使用者同意或由使用者明確觸發，防止應用在沒有使用者參與的情況下自動建立新工作階段。 | 2 |
