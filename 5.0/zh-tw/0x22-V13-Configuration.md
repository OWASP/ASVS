# V13 組態

## 控制目標

應用採用預設組態並在互聯網環境中使用時，必須是安全的。

本章說明在開發、建置和部署階段應如何組態應用，才能達到這一目標。

覆蓋主題包括防止資料洩露、安全管理元件之間的通訊，以及保護秘密。

## V13.1 組態相關文件

本節規定應用文件需要記錄哪些與組態和執行有關的資訊，包括應用如何與內部和外部服務通訊、如何避免服務不可用導致應用失去可用性，以及如何記錄應用使用的秘密。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **13.1.1** | 驗證應用文件完整記錄了所有通訊需求，包括應用依賴的外部服務，以及最終使用者可以提供外部目標位址、再由應用連線該位址的場景。 | 2 |
| **13.1.2** | 驗證應用文件針對所使用的每項服務，規定了最大併發連線數（例如連線池上限），並說明達到上限時應用如何處理，包括採用哪些回退或復原機制來防止拒絕服務。 | 3 |
| **13.1.3** | 驗證應用文件為應用使用的每個外部系統或服務（例如資料庫、檔案控制代碼、執行緒和 HTTP 連線）規定了資源管理策略。策略應包括資源釋放流程、逾時設定和故障處理；實作了重試邏輯時，還應規定重試次數上限、間隔和退避演算法。對於同步 HTTP 請求與回應操作，策略應要求設定較短的逾時時間，並停用重試或嚴格限制重試，以防止延遲級聯和資源耗盡。 | 3 |
| **13.1.4** | 驗證應用文件列出了對應用程式安全至關重要的秘密，並根據組織的威脅模型和業務要求規定了輪替計畫。 | 3 |

## V13.2 後端通訊組態

應用會與 API、資料庫等多個服務或元件互動。這些物件可能屬於應用內部，但不受應用常規存取控制機制管理；也可能完全由外部提供。無論屬於哪種情況，都必須對應用與這些元件之間的互動進行安全組態；必要時，還必須防止相關連線組態被未授權查看或修改。

注意：「安全通訊」章節提供了傳輸中加密指導。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **13.2.1** | 驗證 API、中介軟體和資料層等後端元件，在無法使用應用常規使用者工作階段機制時，會對彼此之間的通訊進行身分驗證。身分驗證必須使用各自獨立的服務帳號、短期權杖或基於憑證的身分驗證，不得使用密碼、API 金鑰或具有特權的共享帳號等長期不變的身分驗證資訊。 | 2 |
| **13.2.2** | 驗證本機服務、作業系統服務、API、中介軟體和資料層等後端元件相互通訊時，使用的帳號只擁有完成任務所需的最低權限。 | 2 |
| **13.2.3** | 驗證服務身分驗證需要使用身分驗證資訊時，呼叫方沒有使用 `root/root`、`admin/admin` 等預設身分驗證資訊。 | 2 |
| **13.2.4** | 驗證應用通過允許清單限制可以通訊的外部資源和系統，包括出站請求、資料載入和檔案存取的目標。允許清單可以在應用、Web 伺服器、防火牆或多個層面共同實施。 | 2 |
| **13.2.5** | 驗證 Web 伺服器或應用伺服器組態了目標允許清單，明確限制伺服器可以向哪些位址傳送請求，以及可以從哪些位置載入資料或檔案。 | 2 |
| **13.2.6** | 驗證應用連線獨立服務時，遵循應用文件為每個連線規定的組態，包括最大併發連線數、達到上限後的處理方式、連線逾時和重試策略。 | 3 |

## V13.3 秘密管理

秘密管理是保護應用所用資料的一項基本組態任務。密碼學的具體要求位於「密碼學」章節，而本節聚焦於秘密的管理和處理。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **13.3.1** | 驗證應用使用金鑰庫等專門的秘密管理系統，安全地生成、儲存和銷毀應用後端使用的秘密，並控制存取權限。此類秘密可以包括密碼、金鑰資料、連線資料庫和第三方系統所需的身分驗證資訊、基於時間的權杖所需的金鑰和種子，以及 API 金鑰等內部秘密。秘密不得寫入原始程式碼或建置產物。L3 應用必須使用硬體安全模組（HSM）等由硬體提供安全保護的方案。 | 2 |
| **13.3.2** | 驗證對秘密的存取遵循最小權限原則。 | 2 |
| **13.3.3** | 驗證所有密碼運算都通過隔離的安全模組執行，例如金鑰庫或硬體安全模組（HSM）。金鑰資料必須始終由該模組安全管理和保護，不得暴露到模組之外。 | 3 |
| **13.3.4** | 驗證秘密已按照應用文件組態到期失效和輪替機制。 | 3 |

## V13.4 非預期資訊洩露

正式環境應經過組態加固，避免洩露不必要的資訊。這類問題單獨出現時往往不構成重大風險，卻經常被攻擊者與其他弱點組合利用。預設關閉這些資訊洩露渠道，可以提高攻擊難度。

例如，隱藏伺服器端元件版本並不能消除修補所有元件的需要；停用目錄清單也不能消除使用授權控制或避免檔案放入公開資料夾的需要，但它確實提高了門檻。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **13.4.1** | 驗證部署產物不包含 `.git`、`.svn` 等版本控制中繼資料。如果確實存在這些目錄，則無論外部使用者還是應用自身都不能存取。 | 1 |
| **13.4.2** | 驗證正式環境中的所有元件都已關閉偵錯模式，避免暴露偵錯功能或洩露內部資訊。 | 2 |
| **13.4.3** | 驗證 Web 伺服器預設不向用戶端顯示目錄清單；只有明確預期提供目錄清單時才可以啟用。 | 2 |
| **13.4.4** | 驗證正式環境不支援 HTTP TRACE 方法，以避免潛在資訊洩露。 | 2 |
| **13.4.5** | 驗證文件（例如內部 API 文件）和監控端點不會暴露，除非明確預期公開這些內容。 | 2 |
| **13.4.6** | 驗證應用不會暴露後端元件的詳細版本資訊。 | 3 |
| **13.4.7** | 驗證 Web 層（例如 Web 伺服器）只向用戶端提供副檔名已明確允許的檔案，防止內部資訊、組態檔案或原始程式碼被意外公開。 | 3 |
