# V8 授權

## 控制目標

授權的作用是確保只有獲得許可的使用方（包括使用者、伺服器和其他用戶端）才能存取資源。為了落實最小權限原則（POLP），應用必須滿足以下總體要求：

* 記錄授權規則，包括決策因素和環境情境。
* 使用方只能存取其既定權限所允許的資源。

## V8.1 授權文件

完整的授權文件有助於確保各處採用一致、可稽核且符合組織政策的安全決策。文件應讓開發人員、管理員和測試人員都能清楚理解並落實授權要求，從而降低未授權存取的風險。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **8.1.1** | 驗證授權文件規定了如何根據使用方的權限和資源屬性，限制其可以使用哪些功能以及可以存取哪些具體資料。 | 1 |
| **8.1.2** | 驗證授權文件規定了如何根據使用方的權限和資源屬性，限制其可以讀取或寫入哪些欄位。這些規則可能還取決於相關資料物件的其他屬性，例如物件當前的狀態。 | 2 |
| **8.1.3** | 驗證應用文件規定了用於作出安全決策的環境和情境屬性（包括但不限於時間、使用者位置、IP 位址或裝置），這些決策包括與身分驗證和授權有關的決策。 | 3 |
| **8.1.4** | 驗證身分驗證和授權文件說明了除功能級、資料級和欄位級權限之外，環境和情境因素如何參與安全決策。文件應列出需要評估的屬性、風險門檻值，以及不同評估結果對應的處理方式，例如允許、質詢、拒絕或提升身分驗證強度。 | 3 |

## V8.2 通用授權設計

應用應在功能、資料和欄位三個層面實施細粒度授權，確保使用方只能存取明確授予其權限的內容。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **8.2.1** | 驗證應用只允許擁有明確權限的使用方存取相應功能。 | 1 |
| **8.2.2** | 驗證應用只允許擁有明確權限的使用方存取相應的資料項，以防範不安全直接物件引用（IDOR）和物件級授權失效（BOLA）。 | 1 |
| **8.2.3** | 驗證應用只允許擁有明確權限的使用方存取相應欄位，以防範物件屬性級授權失效（BOPLA）。 | 2 |
| **8.2.4** | 驗證應用按照文件規定，根據使用方的環境和情境屬性（例如時間、位置、IP 位址或裝置）實施自適應安全控制，並將結果用於身分驗證和授權決策。使用方嘗試建立新工作階段時和現有工作階段存續期間都必須執行這些控制。 | 3 |

## V8.3 操作級授權

授權變更在應用架構的適當層級立即生效，對防止未授權操作至關重要，在動態環境中尤其如此。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **8.3.1** | 驗證應用在可信服務層執行授權規則，不依賴用戶端 JavaScript 等可能被不可信使用方操縱的控制。 | 1 |
| **8.3.2** | 驗證授權決策所依據的值發生變化時，這些變更立即生效。受自包含權杖等機制限制而無法立即生效時，必須採取補償措施：在已經失去權限的使用方繼續執行操作時發出告警，並回復其變更。注意，這種補償措施無法防止資訊已經被讀取或洩露。 | 3 |
| **8.3.3** | 驗證應用根據最初發起請求的主體（例如最終使用者）的權限決定是否允許存取物件，而不是採用代其呼叫的中間服務的權限。例如，使用者攜帶自包含權杖呼叫第一個 Web 服務，該服務再向第二個服務請求資料時，第二個服務應根據使用者權杖作出授權決定，而不能採用第一個服務的機器間權杖所具有的權限。 | 3 |

## V8.4 其他授權考慮

授權方面的其他考慮，尤其是針對管理介面和多租戶環境的考慮，有助於防止未授權存取。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **8.4.1** | 驗證多租戶應用實施了租戶隔離控制，確保使用方的操作不會影響其無權與之互動的租戶。 | 2 |
| **8.4.2** | 驗證管理介面採用多層安全措施，包括持續驗證使用方身分、評估裝置安全狀態和分析情境風險。網路位置或可信端點可以作為降低風險的因素，但不得成為授權存取的唯一依據。 | 3 |
