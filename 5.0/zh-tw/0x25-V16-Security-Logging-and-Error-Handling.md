# V16 安全日誌和錯誤處理

## 控制目標

安全日誌不同於錯誤日誌和效能日誌，它專門記錄身分驗證、存取控制等安全決策，以及繞過輸入驗證、業務邏輯檢查等安全控制的嘗試。安全日誌應提供噪聲少、價值高的結構化資料，供 SIEM 等工具分析，以支援安全檢測、事件回應和調查取證。

除非法律要求，日誌不應包含敏感個人資料；任何記錄到日誌中的資料都必須作為高價值資產加以保護。日誌記錄不得損害隱私或系統安全。應用還必須能夠安全地處理故障，避免不必要的資訊披露或服務中斷。

詳細實作指導請參考參考資料章節中的 OWASP Cheat Sheets。

## V16.1 安全日誌文件

本節要求完整記錄應用技術棧各層的日誌機制，為安全監控、事件回應和合規工作提供基礎。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **16.1.1** | 驗證存在一份清單，記錄應用技術棧各層的日誌記錄情況，包括記錄哪些事件、日誌格式、儲存位置、用途、存取控制方式及保留期限。 | 2 |

## V16.2 通用日誌記錄

本節提供要求，確保安全日誌結構一致並包含預期元資料。目標是讓日誌在分布式系統和工具中可被機器讀取和分析。

安全事件往往涉及敏感資料。如果未經審慎考慮便記錄這些資料，日誌本身就會被歸類為敏感資產，因而需要滿足加密要求和更嚴格的保留策略，並且可能在稽核期間被披露。

因此，只記錄必要內容，並像對待其他敏感資產一樣謹慎對待日誌資料至關重要。

以下要求建立了日誌元資料、同步、格式和控制方面的基礎要求。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **16.2.1** | 驗證每條日誌都包含必要的元資料（例如何時、何地、何人、何事），以便在事件發生時詳細調查事件的時間線。 | 2 |
| **16.2.2** | 驗證所有日誌元件的時間源均已同步，且安全事件元資料中的時間戳使用 UTC 或明確包含時區偏移。推薦統一使用 UTC，以便在分布式系統中保持一致，並避免夏令時切換造成混淆。 | 2 |
| **16.2.3** | 驗證應用只將日誌寫入日誌清單中列明的文件，或發送給清單中列明的日誌服務。 | 2 |
| **16.2.4** | 驗證現有日誌處理工具能夠讀取並關聯各類日誌；最好統一採用通用日誌格式。 | 2 |
| **16.2.5** | 驗證應用記錄敏感資料時，按照相應的資料保護等級執行日誌規則。例如，身分驗證資訊和支付資訊可能完全禁止記錄；工作階段權杖等資料則可能只有在全部或部分經過雜湊或遮蔽處理後才允許記錄。 | 2 |

## V16.3 安全事件

本節定義在應用內記錄安全相關事件的要求。捕獲這些事件對於檢測可疑行為、支援調查和履行合規義務至關重要。

本節概述應記錄的事件類型，但不試圖提供詳盡細節。每個應用都有獨特風險因素和執行情境。

注意，雖然 ASVS 將安全事件日誌記錄納入範圍，但告警和關聯（例如 SIEM 規則或監控基礎設施）被視為範圍外內容，由運維和監控系統處理。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **16.3.1** | 驗證應用記錄所有身分驗證操作，包括成功和失敗的嘗試。還應收集額外的元資料，例如身分驗證類型或所使用的身分驗證因素。 | 2 |
| **16.3.2** | 驗證應用記錄所有失敗的授權嘗試。L3 應用還必須記錄全部授權決策，包括何時存取了敏感資料，但日誌中不得包含敏感資料本身。 | 2 |
| **16.3.3** | 驗證應用記錄文件中定義的安全事件，以及試圖繞過輸入驗證、業務邏輯、反自動化等安全控制的行為。 | 2 |
| **16.3.4** | 驗證應用記錄意外錯誤和安全控制失敗，例如後端 TLS 失敗。 | 2 |

## V16.4 日誌保護

日誌是有價值的取證材料，必須受到保護。如果日誌可以被輕易修改或刪除，它們就會失去完整性，並且在事件調查或法律程序中變得不可靠。日誌可能暴露應用內部行為或敏感元資料，因此也是攻擊者感興趣的目標。

本節定義要求，確保日誌免受未授權存取、篡改和披露，並確保日誌被安全傳輸和儲存在安全、隔離的系統中。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **16.4.1** | 驗證所有日誌元件都對資料進行適當編碼，以防止日誌注入。 | 2 |
| **16.4.2** | 驗證日誌受到保護，免遭未授權存取，且不可被修改。 | 2 |
| **16.4.3** | 驗證日誌通過安全通道傳輸到邏輯上獨立的系統，用於分析、檢測、告警和事件升級。目的是確保即使應用被攻破，日誌也不會遭到破壞。 | 2 |

## V16.5 錯誤處理

本節要求應用在發生故障時妥善、安全地處理，不向外洩露敏感的內部細節。

| # | 描述 | 級別 |
| :---: | :--- | :---: |
| **16.5.1** | 驗證發生意外錯誤或涉及安全的錯誤時，只向使用方傳回通用錯誤訊息，不暴露棧跟蹤、查詢語句、秘密金鑰、權杖等系統內部敏感資訊。 | 2 |
| **16.5.2** | 驗證外部資源存取失敗時，應用仍能安全執行，例如採用斷路器或優雅降級等模式。 | 2 |
| **16.5.3** | 驗證應用在發生故障時（包括發生異常時）能夠妥善、安全地處理，防止出現失效開放（fail-open）的情況，例如在驗證邏輯報錯後仍處理事務。 | 2 |
| **16.5.4** | 驗證應用設定了能夠捕獲所有未處理異常的兜底錯誤處理器。這是為了避免丟失必須寫入日誌文件的錯誤詳情，同時確保錯誤不會導致整個應用處理程序終止，造成可用性喪失。 | 3 |

注意：Swift、Go 以及許多采用常見設計方式的函數式語言不支援異常或全局兜底處理器。使用這類語言時，架構師和開發人員應遵循相應語言、框架和設計模式的慣用做法，確保應用仍能安全處理錯誤、意外情況和安全事件。
